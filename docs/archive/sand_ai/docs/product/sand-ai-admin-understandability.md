# SandAI 管理端可理解性规格

> 状态：前端已按 API 1.14 落地（U-23）；登录态新用户走查仍需管理员会话。
>
> 范围：SandAI 管理端。面向第一次配置 AI 的平台管理员，而不是熟悉接口、模型厂商和内部代码的开发人员。

## 1. 要解决的问题

管理员应能独立完成“接入一个模型并让某个应用环境可使用”的配置。每一步都必须回答：

1. 这是什么；
2. 我应该填什么；
3. 这个值从哪里来；
4. 保存或发布后会影响什么；
5. 选错时怎样回退或验证。

`code`、`adapter`、`route_kind`、`deployment_id`、`driver_code`、`priority`、scope 和
`Bearer` 都是系统术语，不能作为第一次使用时唯一的可见说明。它们可以保留在“高级设置”或
详情中，但页面默认显示业务名称和解释。

## 2. 统一交互规则

### 2.1 页面结构

所有设置型页面按同一顺序呈现：

1. 页面标题下用一句话说明“配置后谁会用到它”；
2. 顶部给出当前步骤和前置条件；
3. 每个字段紧跟简短说明和可展开的“从哪里获取”；
4. 保存前显示影响范围和检查结果；
5. 保存后区分“已保存草稿”和“已发布生效”，并给出下一步入口。

列表默认显示中文业务列；内部标识放到次级列或详情抽屉。搜索同时支持名称和内部编码。

### 2.2 术语与字段规范

| 现有术语 | 默认显示 | 给新用户的解释 | 来源/约束 |
| --- | --- | --- | --- |
| 编码 / `code` | 系统标识 | 业务系统调用时使用的稳定名称；改名会影响已接入的调用方，因此创建后不可改。不是供应商模型名。 | 由平台管理员按命名规则创建；默认建议从名称生成，可在高级设置修改。 |
| 名称 | 显示名称 | 后台中给人看的名称，例如“示例项目材料整理模型”。 | 管理员自定义。 |
| 模型类型 | 用途 | 对话生成、文本向量化、检索结果排序三选一；每项都显示用途和不能做什么。 | 根据该模型的实际能力选择。 |
| 能力 | 可用功能 | 该模型已验证可执行的功能，例如“对话”“工具调用”。 | 来自供应商文档和连接测试；按类型筛选，不允许任意逗号输入。 |
| 服务商适配方式 / `adapter` | 连接方式 | SandAI 已支持的通信协议，不是厂商名称。 | 仅可从受支持适配器中选择；当前可用项要显示协议说明。 |
| 模型部署 | 可用连接 | 将“逻辑模型 + 服务商连接 + 对方的实际模型名”组合成可发布的运行资源。 | 平台管理员创建并通过连接测试。 |
| 能力 | 业务功能 | 某个环境需要的功能，如“对话回答”“文档解析”“扫描件识别”。 | 由系统能力目录提供。 |
| 路由 | 该功能使用谁 | 某个业务功能实际交给哪个已发布模型部署或解析器执行。 | 模板生成；仅在高级设置调整。 |
| 外发策略 | 数据能否离开本地 | 文件和提示词是否允许发往已批准的云服务。 | 管理员按数据合规要求选择，保存前必须明确影响。 |
| 发布 | 让环境生效 | 草稿只可检查；发布后该应用环境的新请求开始使用此配置。 | 发布前完成可用性和数据策略检查。 |

## 3. 新用户主路径

页面应提供“开始配置”向导，默认走以下六步；高级用户可跳到相应管理页。

1. **选择应用和环境**：只展示来自 SandIAM、当前管理员有权配置的对象，并解释“开发、测试、生产相互隔离”。
2. **选择使用场景**：对话回答、文档解析、扫描件识别、知识检索；允许多选。
3. **说明数据边界**：用自然语言选“资料不能离开内网”“可发送到已批准云服务”等选项，再映射为外发策略。
4. **选择已验证的能力组合**：优先推荐模板，并清楚显示每个模板将启用哪些模型/解析器和限制。
5. **检查并保存草稿**：展示“会使用的模型部署、是否会外发文件、缺失项、影响的环境”。
6. **受控测试并发布**：测试仅使用管理员明确选择的非业务样本；通过后发布。页面回显版本、操作者、时间和回滚入口。

没有可发布模型部署时，向导必须直说“还没有可用模型连接”，并跳转到“接入模型”，不能要求用户填写 `deployment_id`。

## 4. 页面改造要求

### 4.1 模型与服务商

- “新增模型”改为“登记逻辑模型”，标题下说明它不等于已能调用的厂商模型。
- `chat` 显示为“对话生成”；`embedding` 显示为“文本向量化（用于知识检索，不能直接回答）”；`rerank` 显示为“检索结果排序（不能直接对话）”。
- “能力”使用按类型筛选的复选项；每项显示用途，默认选与类型相符的基础能力。不得再要求用户用逗号输入内部值。
- 编码显示示例、不可修改原因和命名建议；创建时可自动生成建议值，但必须让用户确认唯一性。
- 服务商页把“适配器”改成受支持协议选择；将 endpoint、API Key、可选请求头拆成受保护字段，并用厂商控制台的获取步骤说明。密钥仍然只写不回显。
- 增加“模型部署”页面或将其纳入接入向导。必须用名称选择服务商与逻辑模型，并单独填写供应商的实际模型名；提供连接测试、草稿、发布和状态，不暴露数据库 ID。

### 4.2 能力路由

- 默认使用“场景模板”而不是空白路由表；模板名称、数据边界和将启用的能力均用中文说明。
- 高级路由表显示“业务功能”“执行资源”“备用顺序”，内部值可在详情中查看。
- 所有能力、驱动和策略的下拉项显示 `中文名称 + 一句话用途 + 数据处理位置`。
- 将数值 `deployment_id` 改为已发布部署的名称选择器；将 `route_kind` 设为系统推导的只读信息；`priority` 改为“主用/备用 1/备用 2”。
- 发布前校验必须在页面上逐项展示，尤其是“模型类型不匹配”“部署尚未发布”“策略禁止向云服务外发”。

### 4.3 文件、任务、检索和 Agent

- 将“运行面 Bearer”显示为“运行凭证”，解释其来自 SandIAM、只保存在当前浏览器会话、需要哪些服务权限，并保留跳转入口。
- 把 `model`、`user message`、`source_block_ids`、`instructions`、`tools`、`review_required` 改为中文业务标签；技术名在帮助中保留。
- 以名称选择允许模型和来源；来源块 ID 仅放高级选项，不要求新用户手输逗号列表。
- 对“检索”“Agent”“人工复核”明确说明：检索只查当前环境私有来源；人工复核只是提示，不会代替业务审批。

### 4.4 调用、用量、审计和总览

- `request_id`、`state`、`action`、`source` 等列提供中文名、状态字典和详情说明；原值保留以便排障和复制。
- 总览不显示 API 版本、`index.total` 等实现细节；改为“管理资源数量”和“最近运行情况”。
- 每个记录页说明它回答的问题：调用记录回答“这次请求发生了什么”，用量回答“消耗了多少”，审计回答“谁改了什么”。

## 5. 需要的契约增量

能力路由当前只接收数值 `deployment_id`，而管理端没有可供选择的部署目录。这使非技术人员无法完整配置。

新增一个向后兼容的只读管理接口（建议 API 1.14）：返回当前管理员可见的模型部署摘要，至少包含
`id`、部署显示名称、逻辑模型名称/类型、服务商名称、供应商模型名、发布状态、外发属性和可用于的能力。
能力配置页只消费这一摘要选择部署；现有保存、发布和运行 API 不变。

## 6. 验收标准

以从未使用 SandAI 的平台管理员为受试者，在不查代码、不问开发人员的前提下完成以下任务：

1. 能说出编码、名称、模型类型、能力、服务商和模型部署分别代表什么；
2. 能从页面指引找到服务商 endpoint 与 API Key 的来源，并知道密钥保存后不可回看；
3. 能完成一个对话模型的登记、部署连接测试和发布；
4. 能为一个测试环境用向导配置“文档解析 + 对话回答”，并在发布前理解数据是否外发；
5. 能在任务页提交一条测试任务、看懂结果、知道来源和人工复核的含义；
6. 能在调用、用量、审计三页分别找到一次测试的运行、消耗和配置变更记录。

验收证据必须包括：上述流程的真实浏览器录屏或截图、前端 `vue-tsc --noEmit` 与生产构建、以及不改变现有 API 回归路径的证据。仅增加说明文字或通过构建不视为验收通过。
